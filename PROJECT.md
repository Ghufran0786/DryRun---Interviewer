# DryRun

DryRun is a local-first, single-user web app for practicing system design mock interviews against an AI interviewer. You sketch on an embedded whiteboard, speak your reasoning, and receive probes and hints while the system captures transcripts, snapshots, and timings for later evaluation. **Roadmap:** 1 Scaffold/shell · 2 Excalidraw + snapshots · 3 Deepgram live STT · 4 Interviewer loop · 5 Interviewer TTS · 6 Vision · 7 Evaluation engine (done) · 8 Reports/PDF/export.

## Design system

Light theme only. Background `#FAFAFA`, surfaces `#FFFFFF`, primary text `#0A0A0A`, secondary text `#6B6B6B`, borders `#E5E5E5` (1px), hover `#F2F2F2`. No other colors in the **app shell** — status uses filled vs outlined dots, weight, and text. Buttons: primary black/white, secondary white/black with border, 6px radius, 2px black focus rings. Typography: Geist via `next/font`; uppercase 11px tracked section labels; `tabular-nums` for timers. Hand-rolled UI in `src/components/ui/` (no component libraries). See PINNED FACT (f) for the Excalidraw exemption.

## Decisions

A/V recording deferred — the timestamped transcript + snapshot bundle is the deliverable. Live suggestions are interviewer-style nudges only (no coaching panel); the Hints tab is removed in Phase 4 and nudges are tagged in the transcript for the report. Phase 8 PDF renders diagrams from stored snapshot PNGs, never from a live Excalidraw instance.

## PINNED FACTS — never violate

**(a) Deepgram audio path:** the canonical path is browser → `ws://localhost:3001` local `ws` proxy (started together with `npm run dev`) → `wss://api.deepgram.com/v1/listen`. Deepgram credentials live server-side only; the browser never receives a key or token. The proxy mints its own fresh JWT internally for every connection using `POST https://api.deepgram.com/v1/auth/grant`, then authenticates upstream with `Authorization: Bearer <JWT>`. `POST /api/deepgram/token` is internal-only and retained solely for the permanent `/debug/deepgram` triage tool; production audio never calls it. **EMPIRICAL RECORD (2026-09-17):** browser-direct `?access_token=<JWT>` fails in this environment with an HTTP authentication handshake failure, close code 1006, and zero messages before any microphone involvement, while the grant itself returned 200 with `expires_in: 300`. DO NOT attempt browser-direct auth again. The proxy forwards ALL client query parameters upstream verbatim and is transparent to Deepgram message types. Proxy control frames use namespaced types (for example `DryRunProxy.Ready`) and MUST be filtered before the transcript/classifier path. If port 3001 is unreachable, the hook surfaces `proxy not running (is npm run dev up?)`, distinct from a Deepgram-side close. `/debug/deepgram` is a permanent triage tool, not scaffolding.

**(b) Excalidraw embed:** import `@excalidraw/excalidraw/index.css`; render inside a container with explicit non-zero height; in Next.js App Router the wrapper must have `"use client"` AND be loaded with `next/dynamic { ssr: false }`.

**(c) OpenRouter vision:** POST `/api/v1/chat/completions` with a content ARRAY — text part FIRST, then exactly one `image_url` part when a fresh board image is included. The chosen model must list `"image"` in `input_modalities`. **Vision turn payload:** at turn dispatch the client captures a fresh board image through the existing SSR-safe lazy Excalidraw export path, canvas-downscales it to at most 1280px on its longest side, encodes PNG as a base64 data URI, and sends it without persistence. Vision captures never create Snapshot rows; snapshots remain event-driven per FACT (d). Inclusion is change-gated with FACT (d)'s scene signature against this session's last successfully image-bearing turn. An unchanged non-empty board sends digest only plus the exact context line `Board unchanged since the last image.` An empty board never sends an image. The classifier receives only the digest and never an image. If capture exceeds 400ms, dispatch without the image and log the omission; do not advance the vision signature so the board rides the next turn. If the generator rejects image input, retry that same turn exactly once without the image and persist the Settings warning `interviewer model rejects image input — choose a vision-capable model.` A turn is never lost to vision. Generator timing logs include `image` and `imageBytes`.

**(d) Interviewer-loop architecture (Phase 4):** turn detection is separate from reasoning. Turn end uses the de-stacked Deepgram/client boundary timing in FACT (h). Each finished turn is classified by a fast cheap model into `stay_silent` / `probe` / `nudge` / `answer_question`; only non-silent outcomes call the main interviewer model. Whiteboard snapshots are event-driven: debounced Excalidraw `onChange` (3–5s idle) + material-change gate (element count/version diff), never on a fixed timer. Send KeepAlive frames on the Deepgram socket during long silences. **TTS gating:** the global `interviewerSpeaking` state follows FACT (k). Phase 3's transcript store supports the required source/suppression concept.

**(e) Reports:** the persisted artifact bundle (transcript + snapshots + interventions + timings) is the source of truth; the PDF is a server-side render of it; evaluation must be re-runnable against any old session.

**(f) Excalidraw exemption:** the Excalidraw canvas and its native UI are EXEMPT from the monochrome rule — fidelity to the real interview tool beats aesthetic purity. Never restyle Excalidraw internals. Monochrome applies to the surrounding app shell only.

**(g) Audio pipeline:** `getUserMedia` audio constraints: `{ echoCancellation: true, noiseSuppression: true, channelCount: 1 }`. ONE `MediaRecorder` per socket connection, started as `recorder.start(250)` — the 250ms timeslice is mandatory (bare `start()` emits nothing until stop, which looks like a connected-but-silent socket). NEVER pause/resume or recreate the recorder mid-connection: the first WebM chunk carries the Opus header and later chunks are headerless. On reconnect, tear down and recreate BOTH the socket AND the MediaRecorder. `ScriptProcessorNode` is FORBIDDEN. (If raw PCM is ever truly needed, use `AudioWorklet` — but v1 uses `MediaRecorder audio/webm;codecs=opus` and NO `encoding`/`sample_rate` params in the URL; the container is self-describing.) TTS gating (Phase 5) happens at the TRANSCRIPT HANDLER — discard/tag results while `interviewerSpeaking` — never by pausing audio. Audio flows continuously so the container header and Deepgram's endpointing state stay coherent. **VERIFIED keyterm syntax:** Nova-3 keyterm prompting uses one repeated plain `keyterm=` query parameter per term or multi-word phrase; no weights and no comma/semicolon/newline joining. The client URL-encodes each value and caps the list at 40 terms.

**(h) Interim/final rule:** Messages with is_final:false are interim — render as a provisional line replacing the previous interim; NEVER persist them. Messages with is_final:true are finalized segments — persist each as one TranscriptEntry with tsMs = elapsedMsSinceSessionStart(startedAtMs). is_final:true may arrive several times within one utterance. speech_final:true marks the end of an utterance; it does not itself carry new text to persist — it fires the utterance-boundary event. **De-stacked boundary timing:** Deepgram waits `utterance_end_ms=2500`; after an `UtteranceEnd` the client waits only 800ms for late finals. A `speech_final:true` starts a 2000ms fallback, replaced by the 800ms timer if `UtteranceEnd` arrives. Compared with 1500ms, the server boundary adds about one second of statement latency; Phase 5 TTS is expected to mask that conversationally, and the longer boundary prevents fragments from reaching the question short-circuit. Stopping the mic flushes pending finalized text instead of discarding the timer/buffer.

**(i) Digest label resolution:** A shape's label is resolved in priority order: (1) Excalidraw-bound text (`containerId` / `boundElements`); (2) spatial assignment — a standalone text element whose center lies inside the shape's bbox, or within 24px of its edges; innermost (smallest-area) containing shape wins; nearest wins on ties; each text element is consumed by at most one shape and then removed from the standalone list. Multiple texts on one shape concatenate in reading order. Arrow endpoints resolve via `startBinding`/`endBinding` first, else spatially by endpoint coordinate (containment, then nearest ≤24px). Rotation is ignored (unrotated bboxes). Ordering of digest lines is deterministic reading order (top-to-bottom, left-to-right).

**(j) Interviewer-loop invariants:** triggers are utterance-end (classifier-mediated), opening (manual Begin button), stall watchdog (50s candidate silence during an active session, at most once per 2 minutes), wrap-up (once, at `interviewDurationMin − 5` elapsed), and manual (`Ask interviewer` button or phase-stepper click). A SINGLE IN-FLIGHT TURN MUTEX permits at most one turn request across ALL triggers; utterance and stall can coincide and React Strict Mode double-invokes effects in development, so guard with a ref, never state. Utterances arriving during flight are buffered and never issue parallel generation calls. When an interviewer turn persists, discard buffered utterances whose candidate finals had already persisted before that turn; only later speech re-arms the pipeline. The mutex MUST release in `finally` for success, 204, HTTP errors, thrown exceptions, and component re-renders. The two-tier brain uses a cheap classifier at temperature 0 returning strict JSON `{action:"stay_silent"|"probe"|"nudge"|"answer_question",advance_phase:boolean,reason:string}`; parse the first `{...}` block and treat ANY parse failure as `stay_silent`. Classification is bypassed as `answer_question` only when the finished utterance has at least 8 words, ends in `?`, and the previous interviewer turn is at least 10 seconds old. Only non-silent actions reach the generator. No two interviewer turns of any kind may persist within 6 seconds; there are no exemptions. Also enforce a 20s floor between interviewer turns, exempt ONLY `answer_question`, opening, wrapup, and manual triggers. Classifier context includes prior interviewer turns so it never repeats a recent question, includes both roles, and excludes suppressed entries. Context is bounded without a freeform summarizer: system header (persona including candidate name, problem, target level, strictness, duration and phase budgets, current phase, elapsed), `phaseNotes` (one line per completed phase), last 12 turns verbatim (both roles, suppressed excluded), and current scene digest. **Legal stall-watchdog resets are exclusively:** a successfully persisted, non-suppressed candidate final or a successfully persisted interviewer turn. Interims, raw audio, suppressed entries, mic state transitions, and attempted/failed requests MUST NOT reset it.

**(k) Interviewer TTS invariants (Phase 5):** TTS uses OpenRouter `POST /api/v1/audio/speech`, which is OpenAI-Audio-compatible and returns raw MP3/PCM bytes. The browser calls only local `POST /api/tts`; `OPENROUTER_API_KEY` remains server-side. The verified 2026-09-18 default is model `mistralai/voxtral-mini-tts-2603`, voice `en_paul_neutral`, and MP3 output, confirmed by OpenRouter's speech reference and live `GET /api/v1/models?output_modalities=speech` catalog. The server logs the response shape and content type of its first successful call; authentication, credits, rate limit, timeout, network, and invalid model/voice failures retain explicit taxonomy. Interviewer text renders immediately and independently of audio. TTS is an asynchronous enhancement: failure adds a small per-message reason and Retry but never delays or removes text. Audio jobs may fetch concurrently but play through one sequential queue and never overlap. `interviewerSpeaking` becomes true only when browser playback starts and remains true until 800ms after natural or manual playback end to cover trailing echo. During that window, finalized Deepgram segments are persisted as `suppressed`, excluded from utterance assembly, and cannot dispatch turns; provisional transcript display and the stall watchdog are paused. The MediaRecorder and Deepgram socket continue uninterrupted per FACT (g). With `Settings.usingHeadphones=true`, barge-in is eligible only after 1.5s of playback and requires sustained candidate speech: at least two non-empty interim results or about 600ms of continuous interims. One stray interim never stops playback. Barge-in stops immediately, clears queued voice, and clears `interviewerSpeaking` immediately because headphones remove echo risk. With headphones off there is no automatic barge-in. Both modes provide Stop on the playing message and the Escape shortcut; manual stops retain the 800ms echo window. The first fragment of a headphone barge-in may be lost while suppression clears; accepted for v1. A persisted `ttsEnabled` status-bar toggle restores exact Phase 4 text-only behavior when off.

**(l) Evaluation invariants (Phase 7):** Post-session evaluation runs only when `Session.status === "completed"`. `POST /api/sessions/[id]/evaluate` assembles transcript + stats + selected snapshot digests, calls `Settings.evaluatorModel` through OpenRouter, validates strict JSON, and stores `evaluationJson` plus `Session.verdict`. Re-runs overwrite prior evaluation output. Every rubric dimension requires evidence items beginning with `[mm:ss]` or `[snapshot:<id>]`. `weightedScore` is always recomputed in application code from dimension scores and rubric weights; model-supplied arithmetic is never trusted. Snapshot images are capped at three total: the `final` snapshot (or latest if none) plus up to two additional snapshots nearest in time to `hld` and `deepdive` phase-advance markers. Evaluator messages follow FACT (c): text parts first, then `image_url` parts. `evaluationJson` records `rubricVersion`, `evaluatorModel`, `evaluatedAt`, stats, and token usage is accumulated on the session. `Settings.resumeText` is optional; empty resume omits the resume block from assembly with no failure. End Interview persists `reconnectCount` and `closeCodesJson` from STT connection diagnostics before marking the session completed.

## Data model

- **Session:** `id` (cuid), `title`, `problem`, `targetLevel` (`SDE-1` | `SDE-2` | `Senior`), `status` (`created` | `active` | `completed`), `currentPhase` (`requirements` | `estimation` | `api` | `hld` | `deepdive` | `wrapup`, default `requirements`), `phaseNotesJson?`, `promptTokens` (default `0`), `completionTokens` (default `0`), `reconnectCount` (default `0`), `closeCodesJson?`, `createdAt`, `startedAt?`, `endedAt?`, `verdict?`, `evaluationJson?`, `sceneJson?` (persisted Excalidraw `elements` + `files`, not `appState`)
- **TranscriptEntry:** `id`, `sessionId`, `role` (`candidate` | `interviewer` | `system`), `kind?` (`opening` | `probe` | `nudge` | `answer` | `phase_advance` | `wrapup`; candidate entries stay null), `text`, `tsMs`, `suppressed` (default `false`; Phase 5 TTS gate), `createdAt`
- **Snapshot:** `id`, `sessionId`, `capturedAt`, `pngPath` (relative under `data/`), `elementsJson`, `trigger` (`auto` | `manual` | `final`)
- **Settings** (singleton): `candidateName`, `defaultTargetLevel`, `classifierModel` (default `google/gemini-2.5-flash`), `interviewerModel`, `interviewerVisionWarning` (persistent capability warning), `evaluatorModel`, `ttsEnabled` (default `true`), `ttsModel` (default `mistralai/voxtral-mini-tts-2603`), `ttsVoice` (default `en_paul_neutral`), `usingHeadphones` (default `true`), `interviewDurationMin` (default `45`), `keyterms` (newline-delimited Nova-3 prompting terms, seeded with candidate name and system-design vocabulary), `strictness` (`Lenient` | `Standard` | `Bar-raiser`), `resumeText`

SQLite file: `./data/dryrun.db` (`DATABASE_URL=file:../data/dryrun.db` in `.env`, relative to `prisma/schema.prisma`).

## API routes

| Method | Path | Purpose |
|--------|------|---------|
| GET, POST | `/api/sessions` | List sessions; create session |
| GET, PATCH | `/api/sessions/[id]` | Fetch session; update status/metadata/current phase; phase overrides append a system `phase_advance` entry |
| POST | `/api/deepgram/token` | Internal-only grant diagnostic used by `/debug/deepgram` |
| GET, POST | `/api/sessions/[id]/transcript` | Hydrate and append finalized transcript entries |
| POST | `/api/interviewer/turn` | Classify an utterance when required, generate and persist one mutex-guarded interviewer turn |
| POST | `/api/tts` | Synthesize interviewer text through server-side OpenRouter TTS and stream MP3 bytes |
| POST | `/api/settings/test-models` | Test classifier, interviewer, and evaluator OpenRouter model IDs |
| PUT | `/api/sessions/[id]/scene` | Autosave whiteboard elements + files |
| GET | `/api/sessions/[id]/snapshots` | List snapshot metadata (no PNG bytes) |
| POST | `/api/sessions/[id]/snapshots` | Store PNG + elements snapshot |
| GET | `/api/snapshots/[snapshotId]/png` | Serve snapshot PNG file |
| GET, PUT | `/api/settings` | Read/update singleton settings |
| POST | `/api/sessions/[id]/evaluate` | Run or re-run rubric evaluation on a completed session |
